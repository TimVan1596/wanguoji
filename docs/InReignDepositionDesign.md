## 1. 真实代码约束

- `Dynasty.succeedRuler()`把前君记录为真实死亡并追加死亡事实，不能用于活人废位。
- 生死验证将实际死亡、合邦/纳土退位、政治终结分开；身后称号依赖真实死亡记录。
- 正常生命周期处理此前主要覆盖现任君主和未登基宗亲。已登基而被废的人需要单独的自然死亡归档路径。
- 王位权威由 dynasty 的 `currentRulerId` 和 ruler `status` 表达；在位地图单位由 Team 的 RULER user/unit 表达；王统和国号另由 house epoch、FactionIdentity 的名称/颜色历史表达。
- WorldHistory 是 canonical 事件；人物纪事只引用同一事件ID，不应另造普通继位事件。
- 存档使用 live runtime → JSON DTO → validation → hydration。冷却月份和个人政治状态必须进入V14 DTO并经严格校验。

## 2. 最小机制

每12个月评估一次，在位国家必须同时满足：正式国家仍有城市、当前君主在位且存活、稳定度≤40或仅余1–2城、36个月内有本国角色明确的真实政治冲击、存在符合条件的真实宗室候选。低稳定度本身不会抽签。

候选必须在事件前已存在于本王室记录、同一国家和王统、与现君有可追溯的非旁支近亲关系、年满16岁、存活、没有既往在位任期、未被废、未死亡或政治终结。按既有亲属优先顺序及出生月份排序，最多检查两人；不生成候选。

真实危机只接受 WorldHistory 可验证的本国受影响角色：都城陷落、帝国分裂、城市叛乱或失城。事件必须在过去36个月内；相同 `historyGroupId` 合并为一项，避免一次围城被重复计数。缺身份角色、外国事件、未来事件不构成资格。

合格后只抽一次 `WorldRandom`。生产默认保守组：首个独立历史事件组0.5%，每多一个独立组增加0.5%，上限1.5%。抽签成功或失败都将该国家冷却60个月；资格不足不启动冷却。控制组2%/每独立组额外2%/上限6%仅供实验比较，不是生产默认值。诊断不抽随机数，成功路径的候选任命也不另抽随机数。

## 3. 状态转换

```text
12个月评估边界
  → 验证国家、现君、真实危机、当前脆弱性、冷却、候选
  → 不合格：不抽签、不冷却
  → 合格：记录尝试月，只抽一次
      → 失败：不写成功事件，保留冷却
      → 成功：预检完整身份与关系
          → 冻结旧任期（活着，deposed，被废）
          → 新君开始新任期，更新 currentRulerId 与候选
          → 重新绑定唯一在位 RULER 单位
          → 验证王位、任期、候选、单位不变量
          → 追加一个 ruler-deposed canonical 事件并挂接双方纪事
```

转换期间如 runtime 不变量检查失败，会恢复新旧 ruler、任位指针、候选和地图用户；成功历史事件只在运行态通过检查后写入。旧君的人口单位改为普通人物，不当作死亡删除，也不再持有王位。

## 4. 生死与离任生命周期

- `deposed` 是独立政治状态，必须 `endReason="被废"`，任期结束月与政治结束月一致。
- 废位时不写 `deathMonth/deathReason`、`chronicle.deathCause`、庙号或谥号；自然寿命计划和关系不变。
- 后续每月扫描已登基、仍是 `deposed` 且到达预定自然死亡月份的人物；在真实到期月标记 `dead`，写真实死亡月和“自然去世”，保留原 `endMonth`、`endReason` 和结束快照，之后才调用既有身后称号规则并记一条死亡事件。
- V14 校验区分活君、活着的被废君、曾被废后真实死亡、普通死亡、合邦退位和纳土退位。人物ID、亲属链和任期史在所有状态下保留。

## 5. 真实事件与展示

新增 `ruler-deposed`，记录国家、月份、旧君/新君ID和姓名、亲属关系、危机事件ID及王统/国号/旗色未变事实。人物大事记通过单一事件ID分别关联旧君和新君。历史卷轴、史家显示“宗室废立”，不写成死亡继位或异姓篡朝。没有真实证据时不写将领、权臣、拥立、密谋或杀害。

本版只允许同王统宗室夺位，不改 factionId、house epoch、国号、旗色。失败没有成功事件。

## 6. 存档方案：V14，不兼容旧版

用户批准彻底放弃 V13 和更早存档，不需迁移。`CURRENT_SAVE_SCHEMA_VERSION=14`。验证器和读取器在 teardown 前明确拒绝低于14的存档，提示“该存档版本已不受支持，请创建新世界。”；不删除、不覆盖文件，不静默部分加载。新世界生成V14；V14须保持世界随机状态、人物、王统、冷却、事件和地图单位的保存/恢复一致。

V14新增权威内容：ruler `deposed` 状态和 `accessionCause="DEPOSITION"`；dynasty `lastDepositionAttemptMonth`；`ruler-deposed` canonical event。validator检查实际同宗关系、成年、旧/新君与事件对应、危机事件ID归属、冷却月与人物状态。不保留V13运行时兼容分支。

## 7. 改动边界与风险

涉及 Dynasty 生命周期、Ruler life validation、V14 schema/export/hydration、WorldHistory/人物纪事、宗谱和君主/历史卷轴呈现、诊断面板、版本/路线图/变更记录及回归测试。

保持正常死亡继位、原异姓篡朝、自然寿限、普通继承选择、城市/战争/人口/外交概率、合邦/纳土/复国、王统与国号既有规则、庙谥授予逻辑不变。无军队拥立、将军、权臣、官职、摄政或政治集团。

主要剩余风险是长局内各类真实危机事件的自然可达率、不同 Team/地图对象运行中的单位解绑边界，以及长时间V14页面性能；需由有限完整模拟和人工运行共同评估。
