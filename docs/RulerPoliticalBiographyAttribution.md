# v0.99931m 君主政治履历与史评归因

## 范围

APP_VERSION `v0.99931m`，package `0.99.142`，WorldSave V13。此版从现有 WorldHistory、君主任期与王统状态派生人物政治履历；不新增 authoritative 存档字段，不改玩法、抽签、RNG、canonical 事件或庙谥规则。

## 审计结论

- 君主大事记原已选择继承候选死亡、攻城/收复、失都、迁都、分裂、复国、建国、称帝、统一、被俘、篡朝、继位、国家终局及外交签约等事件。政治终局另由明确的当事君主 ID 或实际退位终结信息判断。
- 原在位统计只有亲征夺城、失城、内乱、复国。原史评主要依赖任期人口/领土/城市/稳定快照、峰值、流亡和国家终局；篡朝、外交签约、分裂、迁都和候选先逝未形成统一的个人归因证据。
- 新外交签约生产路径可保存 `signatoryARulerId` / `signatoryBRulerId` 和对应称谓；旧事件及未提供签署快照的事件只有国家参与方，不能据此宣称该君主亲自签约。续约记录是既有关系延续，不作为另一场新签约计数。
- `empire-split` 生产构造明确记录反叛方为发起势力、原国为目标势力。失都/迁都只有事件上的君主 ID 能证明直接归属；无 ID 时仅可作任内事件。国家扩张、分裂和外交关系不自动转成君主亲征或个人决策。
- `heir-died` 生产路径记录当时活跃的继承候选及其父君，没有正式册立身份字段。因此人物界面与事件新文案统一称“继承候选”，不称“储君”。候选死亡数据来自人物权威死亡状态，不补造指定储君。
- `dynasty-usurped` 明确有新君 `rulerId`、前君 ID、被排除继承人 ID、两王统和前后国号；普通 `ruler-succession` 另有前/新君 ID。个人纪事现在按势力、月份和这组 ID 将同一夺统展示一次，同时让新君和前君都能看到该政治边界。被排除者仍依据其人物/宗谱关系展示，不伪造血缘。
- `factionId` 是势力持续身份；国号由 `nameHistory` 按事件月份确定；王统由 `houseEpochs` 记录。三者语义不同，国号易改不代表另建一个 faction，也不必然改变王统。
- 旧史评存在将重大失地和末期高稳定并列的解释能力，但统一政治事实尚未进入同一个履历对象；篡朝同月两事件会在个人纪事重复出现。此次只在展示层折叠确切同一边界，canonical 事件保留。亲征夺城和失城统计仍使用既有 chronicle 权威计数，避免再次从城市事件重复累计。

## 修改与证据级别

新增的派生 `politicalFacts` 保留事件 ID、月份、势力 ID、君主 ID/角色、事件类型、事实结果与可信级别。人物直接行为和任内国家事件分开；不能确认个体的事件不写成个人行动。个人在位统计增加本人有签署 ID 的外交协议、任内重大分裂、被迫迁都、本人篡朝开统和继承候选先逝。国家外交关系不累加到“本人签署”；关系续约不另作签约；迁都只计真实 `CAPITAL_FALL` 原因，不再把失都另加成第二项失败。

篡朝事件历史卷轴展示按事件时点读取旧、新国号；确有改号才显示改号。个人纪事按精确 ID 关联同月继位。未改国号不生成改号文本。资格证据去重仅规范化相同证据码，不删不同事件。

## 三项缺陷修复

1. 前君战死/被俘证据码可由普通资格和政治重创路径重复追加；现在在资格派生末端按证据码去重，危机等级、概率及抽签不变。
2. 诊断基础概率桶缺少 `2%`，更新为初始化2%桶，并对新键作零值初始化；抽签参数不读诊断值。
3. 新君的篡朝事件和普通继位事件仅在 faction、同月、前君 ID、新君 ID 全部一致时于个人纪事合并；不同政治事件保留。

## 尚存证据限制

- 旧存档只有国家外交参与方的协议无法追溯签署君主；此类事实不计本人签署。
- 当前没有 formal-designated-heir-at-death 的权威历史事件字段，不能识别“储君早亡”。
- 无君主 ID 的失都、迁都、征服等事实只能作任内背景，不能归因其个人决策/指挥。
- 国号与王统沿革已有独立历史字段；本轮没有改变国史、宗谱结构或历史事实。
- 本地测试无法替代真实 Chrome/Electron 长局的版面、滚动、历史时点称谓和 V13 用户存档检查。
