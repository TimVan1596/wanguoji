# v0.99931p 终结势力档案排序与时间展示

## 范围与数据核对

本版只改善【天下势力→终结】档案排序和时间展示。APP_VERSION 为 `v0.99931p`，package 为 `0.99.147`，WorldSave 保持 V14；不修改生命周期语义、存档结构、历史事件或国家玩法。

现有 `Team` 生命周期把月份索引保存在 `extinctionYear` / `terminationMonth` 这些兼容旧命名的字段中。`markLifecycleExtinct()` 为彻底覆灭记录月份；`markMerged()` 与 `markSubmitted()` 也结束势力生命周期，但另以 `terminationReason`、`terminationTargetFactionId`、`terminationMonth` 记录合邦或纳土。V14 导出为 `extinctionMonth`、`terminationMonth`，Hydrator 分别还原，严格校验要求行政终结具有合法月份；本版没有增加字段或做月份换算。

## 排序规则

新增的 `sortHistoricalFactions()` 是纯派生排序函数，只接收已筛选的势力列表，复制数组后排序，不改变输入。

| 排序项 | 权威字段/数值 | 方向 |
| --- | --- | --- |
| 终结时间（默认） | `EXTINCT` 原因取 `extinctionYear`；`MERGED` / `SUBMITTED` 取 `terminationMonth` | 新到旧 |
| 终结时间 | 同上 | 旧到新 |
| 累计在国 | Team 现有累计实际在国月份函数 / V14 的 `cumulativeActiveMonths` | 长到短或短到长 |
| 建立时间 | `firstFoundedYear` 月份索引 | 新到旧 |
| 复国次数 | `restorationYears.length` | 多到少 |

日期或累计月份缺失时，无论升序、降序均排在有效值之后；终结日期显示为“—”。不从最后一条历史事件推测或回填缺失终结时间。主排序相同时，按建立月份从早到晚、再按稳定 `factionId` 字符序排序；缺少建立月份排在有值记录之后。

势力档案可见性先由既有 `getVisibleFactions()` 决定，然后才排序。仅终结页显示排序框；【全部】【存续】【流亡】仍使用原来的状态分组和累计在国降序排序。排序选择存在 `FactionDetails` 当前组件状态中，返回列表后保留，刷新后回到默认。详情选择继续使用稳定的 `team.name`（factionId），显示国号仍复用既有历史身份/档案标签。

终结页的状态列补充终结类型和月份；原有建立日期、累计在国、城市与复国数据继续显示。长列表排序结果使用 `useMemo` 缓存到筛选、排序、世界月份或势力数组变化时重新计算。

## 自动回归

`FactionListRules.test.ts` 覆盖三类终结日期混排、升降序、累计在国升降序、建立时间、复国次数、缺失值始终末尾、同值日期与 factionId 确定顺序、输入数组不变，以及临时势力和流亡政权的过滤。V14 Validator 测试将两个不同终结类型的月份经 JSON 保存/读取和严格校验后再排序，对比加载前后结果。

自动测试不会验证列表的实际视觉宽度、长局点击路径或人工滚动体验；这些仍由用户 Chrome/Electron Gate 检查。
