# v0.99931q Stage B：真实军事指挥人物与军权体系

日期：2026-10-14  
APP：`v0.99931q` · package `0.99.149` · WorldSave V15  
Stage A：用户已明确批准方案 B、V15 与 V14 不兼容；旧 V14 存档不迁移。

## 实现范围

将领来自已经存在的普通 `User`。用户创建时确定性派生一个成年出生月，不消耗 `WorldRandom`，也不因此进入普通人口自然死亡流程。晋任时才创建永久 `personId`，与可能复用的 `User.id` 分开；人物姓名、出生月、国家任职区间、死亡事实和可核验的攻城事件引用保存在军政注册表中。军事人物不加入 Dynasty、王室或政治宗谱。

每12个月对正式在国势力执行一次任命评估。具有合格候选和足够现存单位时，以5%机会晋任一名候选。首版限制每国2名现役指挥官、2支活动编组，每编组最多12个真实逻辑单位；编组至少包含指挥官和一名其他现存普通单位。没有足够人口或单位时不创建替代对象。

每个编组获得一个真实敌方城市目标。目标按可攻击敌城的稳定城市 ID 顺序确定，外交限制会阻止命令继续推进。Phaser 固定步进对成员单位做受速度上限约束的方向调整；逻辑移动路径也消费同一命令。单位仍经项目现有移动、领土占领、城市围城和攻陷规则行动，不瞬移、不直接改城主。

攻城接触在 City 权威状态中累计到对应编组；原有城市攻陷、首都陷落或复国事件带上真实 `commandId` 和 `commanderPersonId`，由实际贡献最多的编组获得关联履历。普通接触不新建重大历史事件。任内本国战果不会自动计为将领个人战功。

离任、转属、单位战损、指挥官战损及国家终结分别关闭任职或编组；拆除/恢复运行时对象不记作死亡。编组成员转属或真实移除时立即解绑，避免产生悬空成员引用。真实战损仅在现有 `SIEGE_LOSS` / `BATTLE_DEATH` 路径记录人物死亡；废除的职务保留人物档案。流亡/复国没有自动续任。

## V15 与旧档

V15 增加 User 的 `bornMonth` / `militaryPersonId`，以及 `registries.militaryCommandRegistry` 中人物、任职、编组、目标、战果引用和 ID 序列。Validator 检查身份、月份、人物与活动 User、单位与势力、编组容量、唯一成员、指挥官在组、活动任期、目标城市、战果事件和序列是否会复用。

用户已明确授权不兼容 V14。V14 及更早版本被拒绝并提示“该存档版本已不受支持，请创建新世界。”读取预检发生在运行世界 teardown 之前；旧文件不迁移、不删除，也不能被新保存覆盖。新世界需使用新的手动存档槽位保存。

水合导入军事注册表和人物引用，不重新任命、不重选目标、不产生历史事件或额外随机抽签。V15 导出包含完整随机状态和命令 ID 序列。

## 验证和证据范围

自动用例覆盖确定性成年出生月不消费随机数、既有 User 任命、真实成员引用、年度抽签、活动目标、编组转属/离任、逻辑单位实际转向与移动、进入敌方城市格后的真实围城接触归属、City 围城贡献快照、V15 严格引用校验、V14 拒绝且不破坏旧数据，以及现有存档水合回归。

逻辑移动/占领用例调用生产 `stepLogicalMovement` 和 `applyLogicalOccupation`；City 用例调用真实 `registerSiegeContact` 并检查其权威导出。当前项目没有可以脱离 Phaser/Core 窗口外壳、同时保留完整自然战争、人口、外交、城战与人物生命周期的现成多种子长跑运行器。本次没有声称完成完整自然多种子率或5000年性能校准；自动测试的受控路径证明命令如何被执行，不证明自然战争中指挥官出现率、实际攻城率或长期平衡。人工 Gate 要在 Electron 新七国世界检查完整生产运行。

当前尚未通过用户人工观察验证的风险包括：5%年度任命率是否造成合适的军力集中；目标顺序简单且不做路径寻优时，地图上的实际行军是否可读；Phaser 物理步进中的转向是否能在实际地图环境稳定到达目标；自然世界中是否经常遇到候选不足；5000年人物/事件/存档增长规模。若任一现象不合理，本版先收集人工结果，不在此处扩展到将领政治夺权或新军事模型。
